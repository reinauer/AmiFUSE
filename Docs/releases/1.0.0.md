# AmiFUSE 1.0.0

AmiFUSE 1.0 brings together months of filesystem correctness, Windows
compatibility, packaging, and recovery work. The development history since
0.6.0 contains more commits than all previous versions combined.

Read-write access on macOS and Linux is now supported without the
experimental label. Mounts remain read-only by default. Writable Windows
mounts remain experimental because of the specific limitations below.

## Highlights

- **Bundled FastFileSystem:** FFS/OFS images work without obtaining a
  separate handler. The BSD-licensed FastFileSystem v0.2 covers DOS0-DOS7
  and ships with its license, provenance, and verified checksum. Embedded
  RDB handlers and user-supplied handlers retain priority.
- **Upstream dependencies:** AmiFUSE now uses `amitools[vamos]>=0.9.0`
  instead of the AmiFUSE fork, with `greenlet` declared explicitly.
- **Python 3.11-3.15:** installed-package and unit-test CI covers all five
  versions on Linux, macOS, and Windows. Native mount, integration, and
  smoke jobs exercise all three operating systems.
- **Concurrent partition mounts:** independent, nonoverlapping RDB
  partitions can be mounted concurrently, including writable sessions,
  with partition isolation and conflict detection.
- **Windows physical disks:** CF/SD cards and other physical drives can
  be inspected and mounted with disk locking, explicit ownership, and
  cooperative unmounting.

## Filesystem correctness and durability

- Match handler replies to their original packets, retain buffers until
  late replies arrive, and distinguish failed reads from end of file.
- Correct writes past EOF, zero-filled growth, truncation, shared-handle
  sizes and positions, full-volume errors, and cleanup after failed I/O.
- Avoid writing preallocated file ranges twice during copies by deferring
  zero filling until the unwritten tail is needed or must be committed.
- Preserve open-file contents and deferred deletes across renames, hard
  links, replacement, and directory removal.
- Flush handler buffers and the image at the appropriate durability
  boundaries. Wait for outstanding operations during shutdown and report
  failed flushes rather than claiming success.
- Persist freshly formatted volumes correctly, including ADF floppies,
  and reject unsupported geometry or unsafe handler/version combinations.
- Preserve Amiga dates in local time and apply timestamps through mounts.

## Windows mounts and desktop integration

- Fix directory mountpoints, drive-letter ownership, elevated mount
  visibility, Unicode process discovery, and unmounting venv launchers.
- Handle case-only renames where the installed WinFsp supports them, and
  keep directory listings and repeated renames attached to the correct
  object after a handle-based rename.
- Keep metadata-only opens from locking Amiga files, while preserving
  reader/writer offsets, protection checks, and file contents.
- Check Amiga delete protection before WinFsp cleanup and commit metadata
  changes that Windows directory/volume flushes cannot forward to FUSE.
- Distinguish starting, mounted, and unmounting processes in the tray and
  CLI; complete ready unmounts before reporting other failures.
- Escape characters unsupported by legacy console encodings so a
  successful write is not reported as failed merely while printing its
  result.

## Inspection, extraction, and recovery

- Preserve readable RDB partitions before damaged entries; detect loops,
  truncated chains, overlaps, invalid selectors, and disk read failures.
  Refuse writable access when the layout cannot be trusted.
- Offer numeric selectors for unnamed partitions only when the selector
  identifies that exact partition, and report its driver consistently.
- Warn when a directory listing ends early or skips damaged entries,
  naming the affected directory instead of silently hiding the remainder.
- List individual files, preserve hard-link spelling, and show Amiga
  soft links and their targets. Refuse unsupported traversal through soft
  links with an explanation of the path involved.
- Stage extracted files before replacing their destination. Read and
  validate write sources before modifying an image, and report full-disk,
  missing-path, protection, and handler errors more precisely.
- Run inspection and file commands without loading a native FUSE library.

## Upgrading from 0.6

**Python 3.11 or newer is required; Python 3.9 and 3.10 are no longer
supported.** macOS requires macFUSE 5.3.3 or newer. Existing Amiga filesystem
and filename limits still apply; see the README's bundled-handler notes.

For a clean Python environment on macOS or Linux:

```sh
python3 -m venv amifuse-env
. amifuse-env/bin/activate
python -m pip install amifuse==1.0.0
```

Existing environments using the upstream dependencies can upgrade with
`python -m pip install --upgrade amifuse`. If the environment contains
`amitools-amifuse`, use a fresh environment to avoid overlapping imports.

On Windows, use `tools/install-windows.ps1` from this release. It installs
the matching machine68k wheel and the Windows integration extras. The
installer retains its tested machine68k 0.5.0 wheel downloads. Direct pip
installations can now use upstream machine68k 0.5.1 wheels from PyPI for
Windows x64 and Python 3.11-3.15.

## Known Windows write limitations

Use read-only mounts for irreplaceable media, or work on backup images
when testing writable Windows mounts.

- [#424](https://github.com/reinauer/AmiFUSE/issues/424): a particular
  handle-rename/delete sequence can delete the wrong file when another
  handle's close arrives late. The proposed fix in
  [WinFsp #704](https://github.com/winfsp/winfsp/pull/704) has not shipped.
- [#438](https://github.com/reinauer/AmiFUSE/issues/438): a delete-on-close
  open can report success for a protected object that correctly remains
  on disk when another renamed handle shares its old name.
- [#437](https://github.com/reinauer/AmiFUSE/issues/437): a custom WinFsp
  build containing the proposed current-name fix also needs an AmiFUSE
  compatibility update. Applying that upstream patch alone is not a fix
  for this release.

These are writable-mount limitations in the Windows FUSE interface, not
limitations of the FUSE-free file commands or the macOS/Linux interfaces.
Native macOS icon conversion also remains experimental.
